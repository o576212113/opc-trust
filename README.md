本仓库是 OPC 的**信任锚发布渠道**。它只承载制品签名所用的公钥与指纹，不包含任何源代码。

- 代码仓库是私有的；本仓库存在的唯一理由，是让**没有代码仓库权限的人**也能拿到验签所需的公钥。
- 本仓库的内容一旦发布即不应修改（除追加新密钥）。

## 怎么验

把公钥存成本地文件，然后：

```bash
OPC_BUILD_TRUSTED_PUBLIC_KEY=/path/to/opc-build-key.pub.pem opc doctor
```

| 情况 | 结果 |
|---|---|
| 签名有效 | 正常执行 |
| 制品被替换，或换了密钥签名 | `CLI_BUILD_SIGNATURE_INVALID`（退出码 1） |
| 制品未签名 | `CLI_BUILD_SIGNATURE_INVALID` —— 设了信任锚就不接受未签名 |

## 这份签名保护什么

**覆盖**：OPC CLI 制品的内容清单 —— `scripts/opc.mjs` + `scripts/opc/` 闭包 + 各 `apps/*/dist`。
清单里记了源码提交、内容摘要，以及对这些内容的签名。任何一处文件被替换，验签都会失败。

**不覆盖**（重要）：

- **打包后的桌面应用**（`OPC.exe`）—— 它不读这张清单，本签名对它**没有**保护效力。
- **用户数据与数据库完整性** —— 那是另一套独立机制（运行时完整性探测），与本签名无关。
- **加密、身份认证、防逆向** —— 签名不提供这些能力，它只回答"这份文件是不是发布者发的那份"。

## 安全模型与边界

**验签完全离线**：本地 `node:crypto` 用本文件里的公钥做一次数学验证。不联网、无 CA、无 OCSP/CRL、无服务器。

**没有在线吊销。** 如果私钥泄露，没有任何机制能让已发出的副本停止信任旧签名。
只能发布新密钥、公布新指纹、通知用户更新。**旧密钥在技术上永远验得过。**

**信任源于分发，不源于本文件。** 如果攻击者能同时篡改你下载的制品和本页面的公钥，验签就失效。
本页面的公钥应当通过**第二个独立渠道**（发布公告、邮件签名等）核对指纹。
